# CrossInk — Agent Guide

Canonical instructions for AI coding agents working in this repository.
`CLAUDE.md` points here so Claude, Codex, and Cursor agents share one source of truth.

## Project summary

CrossInk is open-source e-reader firmware for ESP32-C3 and ESP32-S3 devices with 800×480
1-bit e-ink displays. It targets Xteink X3/X4, Seeed reTerminal Sticky, and (in the SDK)
Xteink X4 Pro.

**Lineage:** [CrossPoint Reader](https://github.com/crosspoint-reader/crosspoint-reader) →
[CrossInk (uxjulia)](https://github.com/uxjulia/CrossInk) → **this checkout**
([monk-blade/CrossInk](https://github.com/monk-blade/CrossInk)), which adds:

| Feature | Primary locations | Docs |
| --- | --- | --- |
| Gujarati text shaping | `lib/GujaratiShaper/`, hooks in `lib/Epub/`, `lib/GfxRenderer/` | [`docs/gujarati-rendering.md`](docs/gujarati-rendering.md) |
| FreshRSS reader | `src/FreshRss*`, `src/Rss*`, `src/activities/browser/Rss*`, `lib/RssParser/` | [`docs/rss-reader.md`](docs/rss-reader.md) |

Upstream CrossInk scope rules live in [`SCOPE.md`](SCOPE.md). RSS is intentionally
fork-only (upstream lists active connectivity as out of scope). Gujarati is a modular
shaper library with minimal upstream touch points.

At session start, also read [`.claude/CONTEXT.md`](.claude/CONTEXT.md) for durable
repo-specific gotchas (simulator limits, heap baselines, SD single-reader rule, etc.).

## Architecture at a glance

```
Hardware (ESP32 + SD + E-ink + buttons)
  └─ freeink-sdk/          display, input, storage, battery, network SDK libs
       └─ lib/hal/         CrossInk HAL wrappers (HalStorage, HalDisplay, …)
            └─ src/main.cpp runtime loop
                 ├─ ActivityManager + activities in src/activities/
                 ├─ SETTINGS (CrossPointSettings) + APP_STATE (CrossPointState)
                 └─ Reader → lib/Epub/ → SD cache (.crosspoint/) → GfxRenderer → display
```

**Activity model:** Screen controllers derive from `src/activities/Activity.h`. The
`ActivityManager` stack uses `startActivityForResult()`, `setResult()`, and `finish()`.
Allocate in `onEnter()`, free in reverse order in `onExit()`.

**Activity groups:**

| Directory | Purpose |
| --- | --- |
| `src/activities/home/` | Home, library, recent books |
| `src/activities/reader/` | EPUB/XTC/TXT reading, menus, dictionary |
| `src/activities/settings/` | Settings menus, OTA, fonts, RSS/FreshRSS config |
| `src/activities/network/` | Wi-Fi, web server, file transfer |
| `src/activities/browser/` | OPDS and RSS feed/article lists |
| `src/activities/boot_sleep/` | Boot and sleep transitions |

**Reader pipeline (EPUB):** `ReaderActivity` → `lib/Epub/` (parse, CSS, layout,
hyphenation) → section/page cache on SD → `GfxRenderer` → HAL display. Cache busting
depends on font, viewport, alignment, hyphenation, Bionic Reading, Guide Dots, and
related settings.

**State:** User prefs in `src/CrossPointSettings.h` (`SETTINGS`); session/resume state
in `src/CrossPointState.h` (`APP_STATE`). Most persistence lives under `/.crosspoint/` on
the SD card.

**Networking:** Wi-Fi connects only while network activities run; disconnect in
`onExit()`. Web portal sources are in `web/`; firmware headers are generated by
`scripts/build_web.py`. TLS uses wolfSSL (`FREEINK_NET_WOLFSSL`).

## Developer workflow (this fork)

The root [`Makefile`](Makefile) targets Gujarati + FreshRSS development:

```sh
make setup              # .venv + Python deps
make simulator          # build and run SDL simulator
make test               # host tests (Gujarati, RSS, layout)
make firmware           # pio run -e default
make firmware-development  # default + sticky
make verify             # build + test + status
```

Font generation may use an optional sibling wrapper checkout (`CROSSPOINT_WRAPPER`,
default `../crosspoint`) for public font catalogs and FreshRSS fixtures. Generated
fonts and simulator state stay in this repo.

Common validation:

```sh
pio run -e simulator
pio run -e default
pio run -e sticky
pio check -e default --fail-on-defect low --fail-on-defect medium --fail-on-defect high
find src lib include test -name "*.cpp" -o -name "*.h" | xargs clang-format -i
```

Simulator patches belong in the adjacent [`crossink-simulator`](https://github.com/uxjulia/crossink-simulator)
repo unless the change is firmware-side.

## Core rules

- **Role:** Senior embedded systems engineer for ESP-IDF / Arduino-ESP32 work.
- Support both ESP32-C3 (no PSRAM) and ESP32-S3 (PSRAM). Keep shared code safe for the
  C3 unless explicitly capability-gated; stability beats features.
- Cite file paths and line numbers before proposing non-trivial changes.
- Do not assume ESP-IDF or SDK API availability — verify in `freeink-sdk/` or live code.
- Do not claim performance or memory wins without explaining the mechanism (heap churn,
  flash vs DRAM, stack use).
- Justify new heap allocations or explain why stack/static storage is not suitable.
- Explain fixes in plain language where possible.
- After proposing or making a fix, say how to verify on hardware or in the simulator.

## Hardware constraints

- **ESP32-C3** (Xteink X3/X4): single-core RISC-V @ 160 MHz, ~380 KB usable internal RAM, no PSRAM.
- **ESP32-S3R8** (Sticky, X4 Pro): dual-core Xtensa @ up to 240 MHz, 8 MB PSRAM. PSRAM is
  slower than internal DRAM and unsuitable for every DMA/ISR/latency-sensitive buffer.
- Display: 800×480 1-bit framebuffer = 48 000 bytes. Use runtime renderer dimensions.
- One framebuffer: C3 in internal RAM; S3 via `FREEINK_FB_PSRAM`.
- Storage: SdFat over SPI SD (X3/X4/Sticky) or SDMMC (X4 Pro). **One open reader per
  file path on hardware** — close before reopening.

## Resource rules

1. Keep local stack usage small; justify anything meaningfully over 256 bytes.
2. Avoid repeated heap churn in loops — allocate once in `onEnter()`, reuse, free in `onExit()`.
3. Large constant tables: `static const` (flash, not DRAM).
4. Avoid `std::string` and Arduino `String` in hot paths; prefer `string_view`, `char[]`, `snprintf`.
5. User-facing UI strings: `tr(STR_*)`. Logs may be hardcoded.
6. Prefer `constexpr` for compile-time constants.
7. Reserve `std::vector` capacity before push loops.
8. Debounce persistent writes; do not write progress on every page turn.
9. Bare `new` aborts on failure (exceptions disabled). Use `new (std::nothrow)` or
   `makeUniqueNoThrow<T>()` from `lib/Memory/Memory.h`.
10. Prefer `makeUniqueNoThrow<T>()` / `makeUniqueNoThrow<T[]>()` for owned heap allocations.
11. Raw `malloc`/`new (std::nothrow)` only when a C/SDK API takes ownership — comment why.
12. Treat PSRAM as a device capability; gate S3-only allocations and handle failure.

## HAL and platform rules

- Use HAL classes, not SDK classes, in app code.
- File I/O: `FsFile`, not Arduino `File`. Always close files explicitly.
- Button logic: `MappedInputManager::Button::*` enums, not raw GPIO indices.

## C++ / embedded gotchas

- `string_view::data()` is not null-terminated — do not pass directly to C APIs.
- ISR handlers: `IRAM_ATTR`; ISR-read data in DRAM, not flash-only storage.
- Never `xSemaphoreTake()` from an ISR.
- Do not cast unaligned `uint8_t*` to wider pointer types; use `memcpy`.
- No exceptions. No silent `abort()`. Log before returning failure.
- Avoid `std::function` in hot paths; prefer function pointers or small callback structs.
- Keep template use deliberate; explicit instantiation in `.cpp` when needed.

## Error handling

- Recoverable failures: `LOG_ERR(...)` + `return false`.
- Safe continuation: `LOG_ERR(...)` + known fallback.
- `assert(false)` only for truly impossible fatal states.
- `ESP.restart()` only for intentional recovery (e.g. OTA complete).
- Always log before returning failure from allocation, file, parse, network, or hardware paths.

## Activity lifecycle

- Activities are heap-allocated and deleted on exit.
- Allocate long-lived buffers and tasks in `onEnter()`; free in reverse order in `onExit()`.
- Delete FreeRTOS tasks before the activity is destroyed.
- Close open file handles in `onExit()`.
- Typical task stacks: 2048 B (rendering), 4096 B (network/EPUB parsing).

## UI and input

- Do not hardcode `800`/`480`; use renderer dimensions and orientation helpers.
- Layout inside bezel-safe bounds: `renderer.getOrientedViewableTRBL()`.
- Route drawing through `UITheme` / `GUI` where practical.
- List-style screens: prefer FreeInkUI components for row rendering, touch targets, and pagination.

## Build and verification

- PlatformIO is the source of truth.
- Logging: `LOG_INF`, `LOG_DBG`, `LOG_ERR`.
- Host may be macOS, Linux, WSL, or Windows Git Bash — check `uname -s` for platform commands.
- Crash debugging: serial logs, `ESP.getFreeHeap()` / `ESP.getMaxAllocHeap()`, task stack
  high-water marks, cache clears. On S3, also check PSRAM free/largest block.
- Hardware verification: concrete device path, expected UI/log behavior, cache reset if needed.

## Cache format

- EPUB cache: `.crosspoint/epub_<hash>/`.
- Bump format version and document in `docs/file-formats.md` before changing binary layouts.
- Cache identity follows book path hash; rename/move creates a new cache.
- Clear affected `.crosspoint/epub_<hash>/` when testing parser/layout/image/cache changes.

## Git workflow

- Check `git status --short` before edits and before reporting results. Preserve unrelated user changes.
- On merge/rebase/cherry-pick conflicts with upstream PR refs (e.g. `#2608`), read the PR
  intent before resolving — do not blindly keep local or upstream.
- Do not commit unless the user explicitly asks.
- Do not stage `.pio/`, `*.generated.h`, `compile_commands.json`, or `platformio.local.ini`.
- Branch prefixes: `feat/`, `fix/`, `docs/`, `refactor/`, `test/`, `chore/`.
- Commit messages: `<type>: <short summary>` (`feat`, `fix`, `docs`, `refactor`, `test`, `chore`, `perf`).
